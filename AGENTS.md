## Сохранение в Git

- Запрос пользователя «закоммить изменения» означает commit и push в его удалённый репозиторий. Локального коммита недостаточно.
- Проверять, что удалённая ветка содержит созданный коммит; если push не выполнен, прямо сообщать об этом.
- Сохранять исходники, ресурсы, семейства, тесты, инструкции и описание зависимостей, необходимые для сборки на другом ПК. Сборки, кэши и локальные снимки не включать в Git.
- Если пользователь требует сначала сохранить текущее состояние, не начинать последующую разработку до успешного push.

## Глобальная переделка окон

- План и согласования: `Docs/Ui/Redesign_Backlog.md`. Перед работой над дизайном читать этот задачник.
- Пользователь 2026-10-03 потребовал ждать отдельной команды начать. Сам задачник не является разрешением начинать редизайн или запускать команду агентов. Не запускать его по расписанию или автоматически.
- Порядок: развёртки → создание видов и листов → настройки материалов для ведомостей → настройка графики шаблонов видов. Дальнейший порядок задаёт пользователь.
- Работать по одному окну. Сначала аудит настроек, логики и UX, затем тестовая перерисовка по понравившимся макетам SAB-UI-Lab, показ пользователю и явное согласование конкретного окна. Только после этого переносить утверждённый макет в рабочий SAB. Следующее окно начинать по отдельной команде.
- Использовать UI UX Pro Max, Impeccable, Anthropic frontend-design и соответствующие Nice3point Revit Skills; WPF-UI и анимации адаптировать к Revit 2022–2024.
- Предыдущие общие стили полей, отступы и анимации не считать завершённым переносом тестовых макетов. Согласование визуального направления не считать согласованием всех рабочих окон.
- Сохранить текстовый предпросмотр, одну скруглённую цветную рамку ввода и зазор прокрутки. Иллюстративные рисунки листа и схемы в предпросмотр не возвращать.
- В отчётах отличать тестовый макет, применённое рабочее окно, проверки WPF вне Revit и проверки внутри Revit.
