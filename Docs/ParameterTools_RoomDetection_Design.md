# Определение помещения: аудит и проект решения

Дата: 2026-10-09. Основание: ручной сценарий пользователя и исследование документации Autodesk.
Статус: анализ существующего кода и предложение алгоритма. Новый геометрический движок
не реализован и не проверен в модели Revit. Сохранённая исходная версия: `b0c0e273`.

## Основной сценарий — ручной выбор

1. В настройках включить правило с источником «Из помещения».
2. Во вкладке «Источники», в поле «Как выбираем помещение», выбрать
   **«Выбрать вручную после команды»** и сохранить настройки.
3. Выделить экземпляр группы, выполнить «Занести параметры», указать помещение
   или его марку на плане. На 3D используется список помещений.
4. Одно выбранное помещение является источником для всех подходящих элементов выделения.
   Для следующего помещения повторить операцию с другой группой.

Ручной режим уже является значением по умолчанию в `Profile.RoomSourceMode`.
Сохранённый ранее автоматический режим остаётся настройкой профиля; новое значение
по умолчанию не сбрасывает явный выбор пользователя. `Workflow` вызывает `RoomResolver`
только в автоматическом режиме. Ручная запись не должна требовать успешного автоматического
доказательства принадлежности. Отмена выбора не должна запускать автоматический поиск.

Ограничение параметров групп независимо от источника помещения: параметры, запрещающие
разные значения между экземплярами группы, пропускаются с одной сводной строкой на параметр.
Группы не разгруппировываются, их определения не изменяются.

## Что обнаружено в существующем RoomResolver

| Участок | Поведение и последствия |
| --- | --- |
| Отбор помещений по LevelId | Уровень элемента должен точно совпасть с уровнем помещения. Это может исключать подходящие помещения при смещениях, верхних ограничениях и многоэтажных элементах. Уровень полезен для ускорения поиска, но не доказывает принадлежность. |
| Hits | Реальная Z каждой точки заменяется серединой bounding box очередного помещения. Получается проверка проекции XY, возможна ложная связь по высоте. |
| Загружаемые семейства | После проверки точки возвращается результат даже при нуле попаданий. Единственная штатная связь Room, уже найденная ранее, при этом может быть потеряна. Причины расхождения не объясняются. |
| Стены | При попадании осевых точек результат возвращается до проверки обеих сторон. Смещение Width/2 предполагает расположение линии привязки по центру и не учитывает реальные поверхности стены. |
| Перекрытия и потолки | Проверяются точки горизонтальных граней, затем теряется их Z. Само соприкосновение границ не проверяется. |
| Крыши | Отдельной геометрической ветки нет. |
| Неоднозначность и ошибки | Несколько найденных помещений не выбираются произвольно, но список кандидатов и проверенные условия отсутствуют. По общему сообщению нельзя отличить неверную фазу, отсутствие помещений, непопадание точек и неподдерживаемый элемент. |

Эти дефекты установлены по коду. Конкретная причина отказа в пользовательской модели
пока не воспроизведена: модель и нативный запуск Revit в рамках этого исследования недоступны.

## Предлагаемая последовательность автоматического поиска

Автоматический режим включается явно. Он собирает доказательства до записи параметров,
различает отсутствие источника и неоднозначность, сохраняет исходные координаты и фазу.
Неопределённое помещение не заменяется ближайшим и не приводит к очистке существующего значения.

| Элементы | Основной способ | Дополнительная проверка / ограничение |
| --- | --- | --- |
| Загружаемые семейства | Room с явной фазой, штатная точка расчёта помещения, проверка IsPointInRoom в фактических XYZ. | Явную расчётную точку учитывать отдельно от точки вставки. При конфликте штатной связи и геометрии показывать обе причины, не выбирать молча. |
| Двери и окна | FromRoom / ToRoom и штатные точки расчёта с двух сторон. | Это загружаемые семейства. Две комнаты по сторонам допустимы. Выбор «Из помещения», «В помещение» либо ручной выбор должен быть явной политикой; до её задания несколько кандидатов означают неоднозначность. |
| Стены | Обратный индекс границ помещений: элемент границы → связанные помещения. GetBoundarySegments для плана, SpatialElementGeometryCalculator для контактов граней по высоте. | Проверять обе стороны, фактические грани, протяжённость и высоту контакта. Одна стена может ограничивать несколько помещений. Контакт не обязан давать положительный объём пересечения solid. |
| Потолки и крыши | Верхние граничные подграни помещения и соответствующие элементы через SpatialElementGeometryCalculator. | Учитывать настройки расчёта объёмов, скаты, фактическую высоту и отсутствие связи с граничным элементом. Крыша может покрывать несколько помещений. |
| Перекрытия | Собственная проверка верхних/нижних граней и контакта с нижней/верхней границей помещения: пересечение контуров, согласованная высота, геометрические препятствия. | Autodesk указывает, что перекрытия почти никогда не входят в список граничных элементов расчётчика. Нельзя ограничиваться поиском ID в этом списке или XY-проекцией. |
| Размеры, если имеются в виду размерные цепочки | Ручной источник либо отдельное правило по ссылкам размерной цепочки. | Аннотация не имеет универсальной физической принадлежности помещению. Положение надписи не является доказательством. |

API точек расчёта и штатных связей описан в [FamilyInstances](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Family_Instances/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Family_Instances_FamilyInstances_html.html).
Связи геометрии и граничных элементов, ограничения для перекрытий и проёмов — в
[Room and Space Geometry](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Geometry/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Geometry_Room_and_Space_Geometry_html.html).
Таблица — проект нашего алгоритма на основе этих API, а не обещание встроенного универсального метода Autodesk.

## Лучи и отделочные слои

Лучи — дополнительный способ проверки там, где штатных связей недостаточно.
Начальные точки брать на фактических гранях: распределённые точки поверхности и её центра,
с учётом отверстий; направление — нормаль грани. Длину проверки ограничивать явно.
Проверять попадание отрезка в геометрию помещения и препятствия до этого попадания.
Если раньше встречается посторонняя ограждающая конструкция, помещение за ней не принимать.
Отсутствие препятствия само по себе ещё не доказывает принадлежность.

`ReferenceIntersector` ищет геометрию в 3D-виде и зависит от видимости и Section Box.
Проверка препятствий не должна фильтровать только искомый элемент: иначе чужая стена
исчезнет из результата. Нужен контролируемый контекст анализа либо пересечение отрезков
с геометрией элементов без зависимости от видимости пользовательского вида.
См. [ReferenceIntersector](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/36f82b40-1065-2305-e260-18fc618e756f.htm).

Слои одного CompoundStructure и отдельные отделочные стены — разные случаи.
Отдельную отделочную стену нельзя автоматически считать прозрачной для луча по имени
материала или малой толщине. Для неё нужно отдельное явное правило и проверяемая связь
с основной конструкцией; без такой связи результат остаётся неопределённым.

Общая стена двух комнат и единое перекрытие над несколькими комнатами могут иметь
несколько корректных связей. Дополнительные лучи не превращают их в один источник
для скалярного параметра. Нужна ручная операция либо отдельная согласованная бизнес-логика.

## Условия достоверности

- Фаза задаётся явно. `GetRoomAtPoint` возвращает первое найденное помещение;
  для диагностики перекрывающихся помещений нужен сбор всех кандидатов.
  См. [GetRoomAtPoint](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/7dbcac93-ec82-5f60-4a54-a427f3e1cc1e.htm).
- При выключенном расчёте объёмов помещения представлены упрощёнными экструзиями,
  не учитывающими потолки, крыши и перекрытия. Нельзя выдавать эту геометрию за точную
  проверку контактов. Настройку модели молча не менять; сообщать ограничение.
  См. [Plan Efficient Rooms and Spaces](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-Customize/files/GUID-EE0E1BD9-C271-4D84-8BE1-6EA82252DAFE.htm).
- Помещения связанного файла требуют отдельного источника документа, преобразования
  координат и сопоставления фаз. Текущий resolver работает только с текущим документом.
- Для вариантов конструкции не смешивать взаимоисключающие элементы и помещения.
- Переиспользовать один SpatialElementGeometryCalculator в пределах анализа.
  Изменения документа сбрасывают его кэш; предпочтительно завершить анализ до транзакции записи.

## Диагностика будущего алгоритма

Результаты: найдено / не найдено / несколько кандидатов / недостаточно данных /
препятствие / неподдерживаемая категория. В подробностях: ID и категория элемента,
группа, фаза, уровень как справочная величина, метод, ID/номера кандидатов,
количество и координаты проверенных точек, данные контактов, ID препятствия,
настройка расчёта объёмов и исходное исключение при наличии.

Краткая строка должна сразу объяснять следующий шаг, например:
«Дверь 123: помещения 101 и 102 по разным сторонам; выберите помещение вручную»;
«Потолок 456: точный объём помещения недоступен при текущих настройках расчёта».
Не показывать выдуманный процент уверенности. Ограничения параметров групп по-прежнему
выводить одной строкой на параметр, без списка всех комнат и членов групп.

## Порядок реализации и проверки

1. Сохранить независимость ручного выбора; уточнить подписи режима и ограничения автоопределения.
2. Исправить потерю Z, отбор только по LevelId, ранние возвраты и добавить доказательства в диагностику.
3. Добавить индекс границ стен, штатные политики дверей/окон, затем контакты потолков/крыш.
4. Отдельно реализовать геометрию перекрытий, проверку препятствий и отделочных конструкций.
5. Проверить в Revit 2022/2023/2024: смещения и разные линии привязки стен, общую стену,
   дверь с двумя помещениями, высокий/низкий потолок, перекрытие между этажами и над несколькими
   комнатами, наклонную крышу, двусветное помещение, отверстия, вложенные/зеркальные группы,
   разные фазы, перекрывающиеся помещения, выключенные объёмы, отдельные отделочные стены.

Сборка и тесты ядра не доказывают правильность геометрического определения в модели.
