# Проверка записи после завершения транзакции

Ошибка 09.10.2026: ADSK_Этаж, GUID `9eabf56c-a6cd-4b5c-a9d0-e9223e19ea3f`,
сантехнические приборы 5017924, 8680463, 8910174. Запись `6-19 → 6-19 этаж`
возвращала True из Set, но немедленное чтение давало старое значение. Catalog.Write
выбрасывал исключение, Workflow откатывал SubTransaction до завершения основной транзакции.

Дефект порядка проверки подтверждён кодом. Причина задержки обновления в конкретной
модели без её нативной проверки не установлена.

Исправление: Catalog.Write выполняет предварительную валидацию и Set; отвергнутый Set
и реальные исключения остаются ошибками. После Committed основной транзакции Workflow
заново получает каждый элемент и параметр по ID/GUID и сравнивает итоговое значение.
Счётчики и список заполненных параметров строятся по подтверждённым значениям.
При откате транзакции успешных записей ноль. Ошибка окончательной проверки не откатывает
остальные подтверждённые записи; отчёт явно указывает этап после Commit.

Документация Autodesk: окончательные значения достоверны между транзакциями,
обновляющие модули могут изменить их в конце транзакции. См.
[разъяснение Revit R&D](https://forums.autodesk.com/t5/revit-api-forum/document-modification-transactions-parameters-etc/m-p/5461664)
и [Parameter.Set(String)](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/956a1e23-cfe5-a60b-1ff9-0e8e33812774.htm).

Проверка на подменах API: `Tests/ParameterTools.Write`, 11 сценариев, компилируется
фактический Catalog.Write.cs. Подмены не проверяют механизм транзакций Revit.

Нативная проверка остаётся открытой: после установки и перезапуска Revit 2022 повторить
запись для трёх указанных элементов, сверить GUID и итоговое значение в свойствах,
счётчик записей и отчёт, затем отменить операцию штатной командой Undo.
