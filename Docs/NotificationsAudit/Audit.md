# SAB — аудит модуля «Уведомления»

Дата: 17.10.2026, Europe/Moscow. Статус: аудит завершён; изменения поведения и список разрешений не внедрены. Основание — запрос пользователя: вернуть диагностику контуров и совместной работы, автоматически обрабатывать только выбранные и согласованные сообщения.

Уточнение пользователя после аудита: **уведомления, не требующие OK, показывать**. Предложение скрывать отдельные Warning отменено. Дальнейшее согласование касается только конкретных диалогов с обязательным OK; наличие такой кнопки у прежних кандидатов C01/C08 ещё не подтверждено. Актуальный список — в [Approval.md](Approval.md).

## Вывод

Текущая реализация вмешивается в завершение любых транзакций Revit. Она удаляет все сообщения уровня Warning, перебирает способы разрешения Error и при неудаче запрашивает откат с очисткой ошибок. Это существенно шире управления уведомлениями. Два общих переключателя не дают контроля над конкретными сообщениями и последствиями.

Главное исправление: **всё без обязательного OK показывать; автоматический OK разрешать только по точному правилу пользователя для проверенного информационного диалога**. Ошибки, сообщения контура/профиля, занятости и прав редактирования должны оставаться у Revit. Автоматический выбор исправлений, удаления, рассоединения, снятия ограничений и отката в глобальном обработчике следует убрать.

Полный статический анализ каналов перехвата выполнен. Воспроизведение всех состояний в Revit не выполнено; ниже приведена программа такой проверки. Нельзя считать анализ исходников, инвентаризацию API или тесты вспомогательных функций доказательством корректности в живой модели.

## Как модуль работает сейчас

1. На старте SAB загружает `%LOCALAPPDATA%/RevitQuiet/settings.json`. При отсутствии, ошибке чтения или десериализации создаёт настройки с тремя значениями `true`: Enabled, SkipOrdinary, SkipImportant.
2. Постоянно подписывается на `FailuresProcessing`, `DialogBoxShowing`, `DocumentChanged`, `DocumentClosed`, `Idling`. Перехват касается пользовательских команд и транзакций других плагинов, а не только SAB.
3. В `FailuresProcessing` сначала записывает сообщение в локальный JSONL. Для Warning вызывает `DeleteWarning`. Для Error при commit перебирает значения `FailureResolutionType`; `DeleteElements` отодвинут в конец, остальные упорядочены фактически по enum. Первое доступное разрешение применяется автоматически.
4. Если исправление не найдено, произошла перехваченная ошибка, severity отличается от Warning/Error либо превышен счётчик, задаёт `SetClearAfterRollback(true)` и `ProceedWithRollBack`.
5. В `DialogBoxShowing` обрабатывает настроенные `DialogId → int` и специальное предупреждение зависимого удаления. Для последнего читает хвост journal Revit и запускает таймер поиска штатной кнопки OK через Win32.
6. После возврата в `Idling` сохраняет копии журналов, при необходимости открывает выбор папки, показывает до трёх toast. `DocumentChanged` используется для приблизительной привязки Undo к последнему изменению.

По [руководству Autodesk по обработке failures](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Advanced_Topics/Failure_Posting_and_Handling/Revit_API_Revit_API_Developers_Guide_Advanced_Topics_Failure_Posting_and_Handling_Handling_Failures_html.html), глобальное событие вызывается после локального preprocessor. `Continue` сохраняет штатную обработку, `ProceedWithCommit` запускает новый цикл проверки, а rollback с очисткой скрывает диагностику. Следовательно, наблюдаемое исчезновение ошибок соответствует действиям этого кода.

## Дефекты и рекомендации

### P1 — исправить до повторного включения автоматизации

**N01. Автоматическое исправление ошибок без правила.** `NotificationController.cs:138–153`. Проверка «Revit допускает это разрешение» не означает согласия пользователя. `Default` скрывает конкретный смысл действия; кроме удаления enum содержит MoveElements, DetachElements, QuitEditMode, UnlockConstraints, SetValue, SaveDocument и другие варианты. Отодвигание DeleteElements не делает остальные безопасными. Убрать перебор и `ResolveFailure` из глобального модуля уведомлений. Ошибки передавать штатному Revit.

**N02. Отсутствует защита контура и профиля.** `NotificationController.cs:123–151`. Нет проверки режима, категории или GUID: Warning удаляется, Error исправляется, DocumentCorruption откатывается. Подтверждено историей выше. Полностью сохранять нативную диагностику при создании, редактировании, завершении и отмене эскиза; защитить контуры, профили, размеры и связанные ограничения вне зависимости от severity. Не ограничиваться одним GUID разомкнутого контура.

**N03. Отсутствует защита занятости и прав редактирования.** Те же строки. Проверенные символы находятся в `BuiltInFailures.EditingFailures`: OwnedByOther, ElementNotEditable, CannotBorrowBusyContention, HaveNoPermissionToEdit, CannotCheckoutWorksets, UnableToMakeSourceWorksetEditable, OwnElementsOutOfDate, OutOfDateElements, ReloadBeforeMakeEditable, TemporaryChangesTransparentPermissions, TemporaryChangesOutOfDate, WorksetHasChangedInCentralFile. Проверять только `WorksharingFailures` недостаточно. Сохранять все такие failures и соответствующие диалоги, включая Cancel/Retry/запрос владельцу. Не повторять команду и не подтверждать её автоматически. При нераспознанном сообщении оставлять штатный интерфейс.

**N04. Тихий откат очищает весь набор ошибок.** `NotificationController.cs:157–161`. Действие выполняется на транзакции, а не на одной выбранной записи. Скрываются также сообщения, до которых обработчик не дошёл или которые пропустил по переключателю; исчезает возможность показать проблемные элементы. Исключения также превращаются в скрытый откат. В глобальном обработчике убрать `SetClearAfterRollback(true)` и автоматический запрос rollback. При собственном сбое прекратить автоматизацию и сохранить штатную обработку оставшихся failures.

**N05. Опасные значения по умолчанию и восстановление после сбоя настроек.** `NotificationController.cs:23–25,65–69`. Первый запуск, потеря файла и испорченный JSON включают все действия. Нужны выключенная автоматизация и пустой список разрешений. При миграции старые широкие флаги и произвольные DialogResults не должны превращаться в согласованные правила.

**N06. Зависимое удаление автоматически подтверждается вне списка пользователя.** `NotificationController.cs:182–195`, `DeleteWarningButton.cs:19–60`. Даже при пустом DialogResults распознанное предупреждение «Помимо выбранных элементов будут удалены…» запускает нажатие OK. Парсер ограничен конкретным текстом и счетчиком, но отдельного согласия на этот тип нет. Сохранить нативное подтверждение по умолчанию. Возможное правило зависит от проверенного контекста удаления и требует отдельного согласования; в контуре, семье, группе и совместной работе оно должно уступать защите.

### P2 — устранить при переработке правил и диагностики

**N07. Счётчик повторов не соответствует жизненному циклу команды.** `NotificationController.cs:53,125,136,201–209`. Счётчик общий для документа, увеличивается и при пустом наборе failures. Если pending пуст, ранний return не очищает passes. При активной команде Idling может не наступать, при новом действии — обнулить историю. Закрытие документа passes не очищает. Порог 32 не обеспечивает выход из любого цикла и может сработать для другого действия. После отказа от автоматического commit/retry для ошибок этот риск исчезает из основного пути. Повторяющийся разрешённый warning должен отключать собственное правило и возвращать интерфейс Revit; нужен ключ контекста/операции, а не имя транзакции как уникальный ID.

**N08. Произвольные коды диалогов и отсутствие ограничений типа.** `NotificationController.cs:31–32,184,197–198`. Есть только DialogId и int: нет версии, типа события, допустимого действия, проверки смыслового содержимого и защищённого контекста. Пустой DialogId нельзя использовать как правило для всех MessageBox. Успешный OverrideResult означает принятие кода, а не выполнение нужной операции. [Autodesk различает коды DialogBox, MessageBox и TaskDialog](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/49ba2725-74c9-02b3-4321-eac1f2295bd3.htm). Разрешать только проверенный тип и конкретную кнопку; неизвестные варианты показывать. Нельзя подставлять 1/OK универсально.

**N09. Journal/Win32 подтверждение остаётся эвристикой.** `DeleteWarningJournal.cs:14–43`, `DeleteWarningButton.cs:31–60`. Защита от завершённого journal и проверка владельца окна полезны. Но отсутствует строгая связь записи с текущим окном: нет идентификатора операции/позиции чтения; поиск кнопки проверяет форму окна и подписи, а не сам текст предупреждения. Неизвестный язык/версия/состояние должны прекращать автоматизацию. Синтетический native fixture не доказывает попадание в нужный диалог Revit.

**N10. Журнал показывает попытку вместо достоверного результата.** `NotificationController.cs:147,155,159,191–199,207–208`. «Применено разрешение» пишется до подтверждённого commit. После отказа или вмешательства другого обработчика Action не всегда получает окончательный итог. Для скрытых предупреждений Undo может стать доступным, хотя SAB не менял геометрию и отменяется всё пользовательское действие. Нужны EventId, OperationId, этапы Observed/ActionRequested/Committed/RolledBack/Unknown и понятное имя отменяемой операции. Нельзя подписывать запись «исправлено» только по ResolveFailure/отправке кнопки.

**N11. Привязка Undo к удалению недостаточно строгая.** `UndoEligibility.cs:12–15`, `NotificationController.cs:103–118`. Для ожидаемого удаления принимается любое следующее commit с ненулевым deletedCount и совпадающей ревизией, без проверки имени/целевых ID/идентичности операции. Изолированная проверка подтверждает: `Unrelated deletion` удовлетворяет условию. Это риск ошибочной связи при вмешательстве другого плагина, а не доказанный случай в Revit. Нужна более строгая корреляция либо отказ от Undo, когда происхождение действия неоднозначно. Повторная проверка активного документа и ревизии перед PostCommand уже есть и должна сохраниться.

**N12. Диагностика не собирает весь неизвестный каталог.** `NotificationController.cs:123,128,184`. При выключенном модуле нет наблюдения, при выключенном уровне сообщения пропускаются без записи; неизвестные диалоги также не фиксируются. Пользователь не сможет выбрать то, что не попало в журнал. Нужен отдельный, явно включаемый режим наблюдения без подавления; источник, версия Revit/SAB, тип события, GUID/DialogId, severity, контекст и доступные сведения о кнопках. Нельзя обещать тексты всех legacy-диалогов или наблюдение всей UI Revit через эти два события.

**N13. Синхронный ввод-вывод и модальный выбор папки на Idling.** `NotificationController.cs:168–174,214–232`. На каждое сообщение выполняются несколько записей, затем записи рядом с моделью/центральной моделью, включая сеть. Для серверной/несохранённой модели открывается FolderBrowserDialog во время доставки результатов. Это может задерживать работу и неожиданно забирать фокус. Оставить короткую гарантированную локальную запись перед действием; экспортировать пакетами вне критического обработчика только снимки данных, без Document/FailuresAccessor. Папку выбирать в настройках. При сбое локального журнала отказываться от автоматизации.

**N14. Настройки сохраняются неатомарно; отказ может не совпадать с состоянием интерфейса.** `NotificationController.cs:87,169,174,242,400–407`. File.WriteAllText может оставить повреждённый файл; runtime Enabled отключается отдельно от Config.Enabled. Общая кнопка Save меняет несколько полей до успешного сохранения и не возвращает весь снимок при ошибке. Нужны валидация копии, атомарная замена файла, последняя рабочая копия и явное состояние «автоматизация приостановлена». Сбой чтения не должен включать обработку.

**N15. Нет общей границы исключений в событиях.** `NotificationController.cs:124–131,160–161,180–198,201–233`. Получение метаданных, идентификация модели, установка options/result и OverrideResult находятся вне защищённых участков. Ошибка такого кода может выйти в Revit. Оборачивать внешние обработчики; при ошибке не предпринимать новых изменений, отменять отложенные клики и фиксировать диагностическую причину. Уже удалённое предупреждение нельзя восстановить обещанием «fail open», поэтому все проверки должны предшествовать действию.

**N16. Рост памяти и неоднозначные журналы моделей.** `NotificationController.cs:49–54,94–97,215–227`, `ReadableJournal.cs:15–16`. Entries растёт всю сессию и удерживает Document; при закрытии очищается только часть ссылок, pending/passes также требуют жизненного цикла. Unsaved_Title объединяет одноимённые документы. В одной папке все модели/пользователи пишут в один суточный JSONL/HTML; HTML открыт без совместной записи. Нужны ограниченный буфер, отделение DTO от Revit DB, стабильный идентификатор документа/сессии, файлы по модели/пользователю и последующее объединение. Общая центральная папка не должна быть обязательным местом живой записи.

**N17. Интерфейс и инструкция обещают больше контроля, чем реализовано.** `NotificationController.cs:376–380`, инструкция `SAB_HTML_Uvedomleniya.html:7–9`. Доступны только два широких уровня; списка предупреждений и согласования отдельных действий нет. Слово «поддерживаемые» в инструкции не раскрывает, что Warning фактически скрывается без отбора. В toast есть текст и ID, но нет штатного Show/выбора проблемных элементов; для разорванного контура это не заменяет родной диалог. Нужны отдельные правила с примером, последствиями и состоянием согласования. Функциональное описание интерфейса дано как предложение; UI не перерабатывался и визуальный аудит не выполнялся.

**N18. Основные обработчики не покрыты существующими тестами.** `Tests/Notifications/Verify.ps1`, `NativeButton.ps1`, `CompactToast.ps1` проверяют parser, HTML, карточку, таймер и вспомогательную привязку Undo. Нет интеграционных тестов Failures/Dialog, защищённых режимов, занятости, смешанных batches, миграции конфигурации, другого подписчика и выхода из повторной команды. Старые скрипты загружают отдельные bin/Notifications2023/2024, а не обязательно актуальную production-сборку. Положительный результат этих тестов не означает исправления двух пользовательских проблем.

## Матрица режимов Revit

Таблица задаёт требуемое поведение новой политики; ни одна строка не означает согласованное разрешение скрывать уведомления.

| Режим / сценарий | Что может потребовать решения | Требуемое поведение SAB |
|---|---|---|
| Обычное моделирование | Дубли, пересечения, невидимость, параметры | Все сообщения без обязательного OK показывать; автоматический OK — только по выбранному и проверенному правилу |
| Создание контура | Разрыв, пересечение, короткий отрезок, отсутствие петли | Весь контекст контура оставить Revit |
| Изменение контура / Finish / Cancel | Контуры перекрытия, потолка, крыши, площадки, вырезов | Сохранить диагностику, Show и возможность исправить/отменить |
| Изменение профиля | Стена, выдавливание, семейство, траектория | Сохранить диагностику всех severity |
| Лестницы, пандусы, ограждения | Границы, подступёнки, площадки, связи | Сохранить штатное решение; не выбирать Reset/Delete автоматически |
| Область обрезки, заполненная область, область плана | Недопустимая петля/геометрия | Считать защищённым редактированием контура |
| Редактор семейств / изменение типа | Формулы, размеры, переопределение, потеря геометрии | Ошибки и смысловые предупреждения показывать; на первом этапе не автоматизировать этот контекст |
| Контекстная модель, массы | Эскизы, формы, потерянные основы/зависимости | Штатный интерфейс, включая Finish/Cancel |
| Изменение группы, сборки, массивов | Распространение, исключение/удаление участников | Не подтверждать за пользователя; не снимать ограничения |
| Варианты конструкции | Несовместимые ссылки, удаление варианта | Не выбирать действие автоматически |
| Занятый элемент / рабочий набор | Владелец, заимствование, недостаточные права | Всегда показать; сохранить Cancel/Retry/запрос и не повторять действие |
| Совместная модель, обычная правка | Обычные warnings + изменившееся владение | Первую версию правил ограничить: в workshared ничего не скрывать; расширять отдельно после проверки |
| Синхронизация / Reload Latest / relinquish | Центральная модель, конфликт, очередь, отказ сети | Всегда штатные диалоги; не использовать одно событие cloud progress как универсальный индикатор |
| Открытие, создание local, detach, audit, upgrade | Существующий local, версии, восстановление | Не подтверждать/перезаписывать автоматически |
| Save / Save As / Close | Сохранение, замена, отказ, отмена | Всегда штатные действия; особенно не сопоставлять пустой DialogId |
| Удаление и зависимое удаление | Уровни, виды, марки, размеры, основы | Подтверждать вручную, пока отдельное правило не выбрано и не проверено |
| Ограничения и зависимости | Unlock/Detach/QuitEditMode/перестроение | Не выбирать автоматически, даже если API разрешает |
| Помещения / пространства / зоны | Избыточность, границы, объём, высоты | Показывать; выбор конкретного информационного предупреждения согласовывается отдельно |
| Связи / общие координаты / Copy-Monitor | Координация, изменения площадок, типы, потеря связи | Показывать; не подтверждать сохранение координат и принятие изменений автоматически |
| Импорт / вставка / загрузка семейства | Потеря вставок, замена типов, частичный результат | Ошибки и подтверждения показывать; не считать все Warning несущественными |
| Команды SAB / стороннего плагина | Локальный preprocessor, группировка транзакций | Не вмешиваться глобальным разрешением Error; учитывать чужую обработку |
| Undo / Redo / rollback / без активной модели | Ошибки отмены и восстановления | Ничего не разрешать и не откатывать повторно; отменять отложенный OK |

В API 2022–2024 проверенные публичные свойства Document не содержат общего Sketch/EditMode-флага. `IsModifiable`, `IsReadOnly`, `IsFamilyDocument`, имя транзакции и состояние созданного плагином SketchEditScope по отдельности не доказывают, что пользователь находится в нужном UI-режиме. Детектор контекста надо проверять на реальных командах. Пока контекст неоднозначен, автоматизацию не выполнять. Защиту следует строить в несколько слоёв: разрешение только точного правила, запрет защищённых failure, проверенный контекст, неизвестное → штатный Revit.

`IsWorkshared` не означает, что любой элемент занят. Однако временное выключение автоматизации для всей совместной модели даёт консервативный первый этап. Для последующего расширения нельзя полагаться только на `GetCheckoutStatus`: [Autodesk предупреждает о кэшировании статуса владения](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/ae7857a0-4e9b-f9c1-84c7-8b250af68068.htm). Окончательные ошибки Revit должны оставаться видимыми.

Отдельный `RollbackOnError` параметризации относится к её собственной транзакции: собирает Issues, отменяет операцию при Error/DocumentCorruption; код проверяет результат commit. Это не глобальный suppressor и не основание удалять локальную защиту транзакций всех модулей. Изменять его автоматически в рамках переработки «Уведомлений» не следует; доставку Issues проверить при интеграции.

## Предлагаемый порядок принятия решения

1. Автоматизация выключена или не может доказать применимость правила → никаких действий с failure/dialog.
2. Ошибка, защищённый режим, права/занятость, открытие/сохранение/синхронизация/восстановление → штатный Revit, даже если найдено правило.
3. Нет точного согласованного правила для GUID и проверенного контекста либо для DialogId + типа + кнопки + версии → штатный Revit.
4. Есть неизвестное/защищённое сообщение в том же наборе → оставить весь набор; не скрывать часть до определения состава.
5. Исходное сообщение и решение не удалось сохранить локально → штатный Revit и остановка автоматизации.
6. Сообщение без обязательного OK оставить видимым; не вызывать DeleteWarning. Уровень Warning и GUID сами по себе не доказывают наличие модального окна с OK.
7. Для отдельно разрешённого и проверенного информационного диалога ответить только его конкретным OK. Подтверждения изменения модели оставить ручными. Не менять транзакцию, не подбирать resolution и не запрашивать новый commit.
8. Повтор/несовпадение контекста/сбой → отключить действие правила для текущей операции, отменить отложенное нажатие, вернуть штатный интерфейс; не запускать retry и не скрывать rollback.

Скрытие Warning означает удаление сообщения Failure API; это не нажатие OK и не исправление модели. Штатный список предупреждений после commit также нужно проверять: нельзя обещать сохранность всех предупреждений после DeleteWarning. Для режима «только наблюдать» не вызывать DeleteWarning/ResolveFailure/OverrideResult вообще.

Правило должно хранить идентификатор, действие, scope, версии, ограничения, согласование и ревизию. Отдельные действия: показать; записать без вмешательства; подтвердить проверенный информационный OK. Скрытие Warning без обязательного OK, автоматическое исправление ошибок и универсальный «пропустить всё» в эту модель не включать. Импорт/обновление SAB не добавляет активные разрешения самостоятельно.

Предметный список с реальными GUID и последствиями подготовлен в [Approval.md](Approval.md). Все пункты сейчас имеют статус **не согласовано / показывать**.

## Проверки и критерии приёмки

Выполнены 11 изолированных проверок текущих исходников parser/UndoEligibility: распознавание образца реального journal из репозитория; отклонение завершённого диалога, следующей команды, ошибки, нескольких warnings, чужого текста и пустой строки; подходящая транзакция, изменившаяся ревизия, чужая транзакция, отсутствие удалённых элементов. PASS означает только соответствующий результат этих функций. Дополнительно воспроизведено слабое сопоставление произвольного удаления — это дефект N11, не успешная проверка безопасности.

Запуск доказательств:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Audit-Notifications.ps1 -IncludeLocalHistory
```

Нужен Windows PowerShell 5.1 для метаданных mixed-mode API 2022. `-IncludeLocalHistory` читает локальный журнал и обновляет обезличенный CSV; без него выполняются helper-проверки и инвентаризация API. Evidence фиксирует хеши исходников/API/журнала. Это диагностический скрипт, не тест исправленной production-политики.

Все следующие интеграционные сценарии имеют статус **NOT RUN** и обязательны перед поставкой изменения для поддерживаемых Revit 2022/2023/2024. Нужны отдельная тестовая модель и два пользователя для владения; не проверять зависимое удаление на рабочем проекте.

| № | Проверка | Критерий |
|---|---|---|
| R01 | Первый запуск, нет settings | Автоматизация выключена, разрешений нет |
| R02 | Повреждённый JSON/ошибка записи | Ничего не включается; причина доступна пользователю |
