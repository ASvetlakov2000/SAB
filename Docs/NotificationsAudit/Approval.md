# Уведомления SAB — предложения по автоматическому OK

17.10.2026. Уточнение пользователя: **все сообщения, не требующие нажатия OK, показывать**. Это принятое требование. Ни один конкретный автоматический ответ OK пока не согласован и не включён. Этот документ заменяет первоначальное предложение скрывать выбранные Warning.

## Правило

- Немодальные сообщения и сообщения без необходимости подтверждения OK оставлять видимыми в Revit.
- Наличие кнопки OK само по себе не разрешает автоматизацию. Нужно знать, подтверждает она прочтение либо разрешает изменение/откат операции.
- Автоматический OK рассматривать только для отдельно выбранного, проверенного информационного диалога, где подтверждение не исправляет, не удаляет и не изменяет модель и не повторяет неудачную команду.
- Контуры/профили, занятость/права, ограничения, сохранение, синхронизация и восстановление оставлять штатному Revit, включая случаи с единственной кнопкой OK.
- Неизвестный диалог или неоднозначный контекст показывать. Пропадание сообщения через DeleteWarning не считать эквивалентом нажатия OK.

## Кандидаты на автоматический OK

У следующих сообщений в локальной истории известны текст и FailureDefinitionId, **но не подтверждены форма окна, необходимость OK и код ответа**. Поэтому это условные кандидаты для проверки и выбора, а не готовые правила. Если конкретное сообщение показывается без обязательного OK, его всегда оставляем видимым по требованию пользователя.

| Код | Сообщение | Предложение при наличии обязательного информационного OK | Условия | Статус |
|---|---|---|---|---|
| C01 | Созданные элементы не видны на текущем виде | Можно предложить авто-OK | Только сообщение о результате уже выполненного создания; подтверждение не отменяет/не повторяет операцию; обычный проект вне защищённых режимов | Кандидат: кнопки/эффект не проверены, не согласован |
| C08 | Смежные области вида объединились при нулевом разрыве | Можно предложить авто-OK | Только уведомление об уже выполненном объединении; OK не является разрешением выполнить объединение; вне редактирования контура/профиля | Кандидат: кнопки/эффект не проверены, не согласован |

После согласования и проверки автоматическое подтверждение фиксировать в журнале; можно показывать краткое уведомление SAB с исходным текстом. Это предложение не даёт разрешения автоматически отвечать другим похожим сообщениям.

## Где автоматический OK не рекомендован

В таблице описано поведение, если сообщение требует OK. Если OK не требуется, сообщение остаётся видимым без вмешательства.

| Код / группа | Сообщение или ситуация | Предложение | Причина |
|---|---|---|---|
| C02 | Повторяются значения «Маркировка типоразмера» | Ручной OK | Важна проверка документации и идентификации типов |
| C03 | Идентичные экземпляры в одном месте | Ручной OK | Дубли геометрии и количеств в спецификациях |
| C04 | Перекрываются объёмы помещений | Ручной OK | Ошибка расчёта/высот помещений |
| C05 | Несколько помещений в одной области | Ручной OK | Избыточные помещения и некорректные площади |
| C06 | Объединённые элементы не пересекаются | Ручной OK | Требуется проверить соединение; не выполнять Unjoin за пользователя |
| C07 | Для связи требуется просмотр координаций | Ручной OK | Можно пропустить изменения смежной модели |
| D01 | «Помимо выбранных элементов будут удалены…» | Ручной OK | Разрешает дополнительное зависимое удаление |
| Контур/профиль | Разрыв, пересечение, наложение, короткая линия, пустой/неверный эскиз | Ручное решение в штатном диалоге | Нужны Show, исправление геометрии, Finish/Cancel |
| Совместная работа | Чужой владелец, рабочий набор, недостаток прав, отказ заимствования, устаревший local | Ручное решение в штатном диалоге | OK не устраняет причину; необходим выход из команды без автоматического retry |
| Зависимости | Рассоединение, снятие ограничений, потеря основы, невозможность создать/вырезать форму | Ручное решение | Подтверждение может изменить модель или откатить действие |
| Удаление/частичный результат | Удалённые элементы, потерянные вставки, автоматическое исправление семейства | Ручной OK | Пользователь должен видеть потерю/изменение данных |
| Файлы/связи | Save/Close, замена local, перезапись, несохранённые общие координаты | Ручное решение | Выбор определяет сохранность данных |
| Синхронизация/восстановление | Sync, Reload Latest, центральная модель, отказ сети, upgrade, detach, audit | Ручное решение | Важен контекст и возможность отмены/восстановления |
| Ошибки/неизвестное | Любые Error/DocumentCorruption и неизвестные диалоги | Ручное решение | Нельзя автоматически подтверждать ошибку по одной подписи кнопки |

## Что проверить перед включением выбранного OK

1. Сообщение действительно останавливает работу до ответа OK, а не является обычным немодальным предупреждением.
2. Зафиксированы конкретный тип окна/идентификатор/содержимое, контекст и соответствующий код OK; один GUID недостаточен.
3. Подтверждение означает только прочтение, не изменяет решение пользователя, не удаляет/не исправляет элементы и не повторяет команду.
4. В контуре, профиле и совместной работе правило не срабатывает; штатный выход остаётся доступен.
5. Неизвестное сочетание версии, текста, типа окна или кнопок остаётся видимым.

Принято: все сообщения без обязательного OK показывать. На выбор вынесены только C01/C08 как условные кандидаты. Можно не разрешать ни одного автоматического OK.
