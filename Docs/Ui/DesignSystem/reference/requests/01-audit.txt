# SAB — поиск эталонного окна для разработки дизайн-системы

## Роль и задача

Ты выступаешь как Senior WPF/XAML Developer и UI/UX Architect.

Работаешь с существующим проектом плагинов SAB для Autodesk Revit.

**Главная цель — найти в проекте SAB наиболее подходящее WPF-окно, которое можно использовать как основу для создания единой дизайн-системы всех интерфейсов плагина.**

Нам необходимо выбрать реальное окно, в котором используется максимальное разнообразие элементов управления WPF.

Это окно будет использоваться для сравнения трёх дизайн-концепций:

1. Fluent Light.
2. Fluent Compact.
3. Minimal SaaS.

Впоследствии на его основе будет сформирован единый визуальный стандарт SAB.

---

## ЭТАП 1. Анализ существующих окон

Изучи структуру репозитория SAB.

Найди все существующие:

- Window.
- UserControl.
- Page.
- ResourceDictionary.
- ControlTemplate.
- DataTemplate.

Проанализируй XAML и связанные с ним файлы C#.

Учитывай не только элементы, непосредственно объявленные в XAML, но и компоненты, подключаемые через UserControl, шаблоны и общие ресурсы.

Если интерфейс создаётся динамически из C#, также учитывай его состав.

Для каждого найденного окна определи:

- Название окна.
- Название модуля.
- Путь к XAML.
- Назначение.
- Размеры и структуру.
- Количество различных элементов управления.
- Используемые пользовательские компоненты.
- Сложность компоновки.
- Наличие нестандартных состояний и оформления.

Не изменяй исходный код на этапе анализа.

В частности, проверь наличие:

**Дополнительные элементы**

## ЭТАП 3. Поиск наиболее подходящего окна

Сравни все найденные окна и составь рейтинг пяти лучших кандидатов.

Оценивай их по следующим критериям:

| Критерий | Вес |
|---|---:|
| Разнообразие интерактивных компонентов | 35% |
| Разнообразие компоновки и контейнеров | 20% |
| Наличие таблиц, списков и сложных элементов | 15% |
| Разнообразие состояний элементов | 15% |
| Пригодность для визуальной демонстрации | 10% |
| Возможность запуска вне Revit | 5% |

Не оценивай пригодность только по количеству строк XAML или общему количеству элементов.

Например, окно со ста одинаковыми CheckBox менее интересно, чем окно с Button, ComboBox, TextBox, TabControl, DataGrid и несколькими вариантами группировки.

Предпочтение отдавай окнам, которые позволяют продемонстрировать максимальное разнообразие реальных сценариев SAB.

Для пяти лучших кандидатов подготовь сравнительную таблицу с оценками и обоснованием.

## ЭТАП 4. Выбор эталонного окна

Выбери один наиболее подходящий интерфейс.

Объясни:

1. Почему выбран именно он.
2. Какие элементы управления в нём присутствуют.
3. Какие разновидности компонентов он позволяет продемонстрировать.
4. Какие компоненты SAB в нём отсутствуют.
5. Насколько удобно использовать его для демонстрации трёх дизайн-концепций.
6. Можно ли запустить его отдельно от Revit.

Если выбранное окно не содержит всех используемых элементов, не отказывайся от выбора.

Предложи создать на его основе отдельное демонстрационное окно **SAB UI Showcase**, которое объединит:

- Компоновку реального выбранного окна.
- Основные реальные элементы управления.
- Недостающие типы компонентов из других окон SAB.
- Демонстрационные состояния элементов.
- Примеры отображения таблиц, списков и параметров.

Важно: SAB UI Showcase должен быть отдельным тестовым интерфейсом, а не изменением рабочего окна плагина.

Используй реальные ресурсы и компоненты SAB. Если для демонстрации требуются изменения, не затрагивай действующую бизнес-логику.

---

## ЭТАП 5. Демонстрация состояний

Для разработки полноценной дизайн-системы важно проверить не только внешний вид компонентов, но и их состояния.

Предусмотри возможность демонстрации:

- Default.
- Hover.
- Pressed.
- Focused.
- Selected.
- Disabled.
- Error.
- Warning.
- Success.
- Empty State.
- Loading.

Используй только состояния, применимые к соответствующим компонентам.

Например, для TextBox необходимо показать обычное состояние, фокус, ошибку и Disabled.

Для Button — обычное состояние, Hover, Pressed и Disabled.

Для DataGrid — выделенную строку, пустую таблицу, заполненную таблицу и редактируемые ячейки.

Не пытайся создавать одно универсальное состояние для всех элементов управления.

## ЭТАП 6. Подготовка визуального эталона

Если технически возможно, запусти выбранное окно и получи скриншот существующего дизайна.

Для этого допускается использовать отдельное WPF Preview-приложение с тестовыми ViewModel, если окно не зависит непосредственно от Revit API.

Если запуск невозможен, объясни техническую причину.

Не создавай искусственный скриншот и не представляй его как результат реального запуска WPF.

При наличии графического окружения подготовь скриншоты:

1. Исходного окна.
2. Основных элементов управления.
3. Таблиц и списков.
4. Дополнительных состояний элементов.

Эти материалы будут использованы как отправная точка при разработке нового дизайна.

Предоставь:

1. Количество обнаруженных WPF-окон и компонентов.
2. Перечень реально используемых типов элементов управления.
3. Рейтинг пяти наиболее подходящих окон.
4. Название и путь выбранного эталонного окна.
5. Обоснование выбора.
6. Перечень отсутствующих в нём компонентов.
7. Предложение по структуре SAB UI Showcase.
8. Скриншоты, если удалось выполнить реальный запуск.
9. Рекомендации для последующего создания дизайн-системы.

### Важное ограничение

На данном этапе не изменяй существующие рабочие окна, ViewModel, Binding, Command и бизнес-логику.

Основная задача — исследовать интерфейсы SAB и выбрать наиболее репрезентативный пример.

Не создавай полноценную новую дизайн-систему до завершения выбора эталонного окна.

## Начни выполнение

Проведи аудит всех XAML-интерфейсов в текущем репозитории SAB.

Найди наиболее подходящее окно, которое покрывает максимальное количество различных UI-компонентов.

После анализа представь пять лучших кандидатов, выбери один основной и предложи, как на его основе сформировать SAB UI Showcase для дальнейшего сравнения Fluent Light, Fluent Compact и Minimal SaaS.
