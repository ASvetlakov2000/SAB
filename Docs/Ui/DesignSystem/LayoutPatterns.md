# SAB UI Layout Patterns

Структурные схемы задач, подчинённые [текущей Specification](Specification.md), [Workflow](Workflow.md) и STATUS.json. Не новый стиль и не обязательная одинаковая геометрия всех окон. Старые живые образцы0.1 исключены из active csproj; полный набор7 текущих примеров ещё не реализован — см. [coverage](component-coverage.csv) и [план](CoveragePlan.md). Схемы не добавляют функций модулю.

| Схема | Когда выбирать | Структура WPF | Правило действий / прокрутки |
|---|---|---|---|
| Compact Dialog | Одно решение, 1–3 поля, подтверждение | Grid Auto/Auto/Auto, максимум ширины текста | Основное действие справа; диалог не растягивать на весь экран |
| Settings Form | Настройки одного сценария с зависимостями | Grid с отдельными смысловыми карточками, подписи над полями; AdaptiveSettingsGrid только при проверенной применимости | Ограниченная область полей прокручивается; footer доступен; source Visibility сохраняется; heading icons не добавлять |
| Data Manager | Много однотипных строк и массовые операции | Grid Auto/*/Auto: настройки/группы действий, поиск если предусмотрен функцией непосредственно над DataGrid, status/footer | Один маршрут добавления по039, виртуализация; реальное empty state, не подмена алгоритма |
| Master–Detail | Список объектов и подробный редактор каждого | Grid */Auto/*; слева список, справа выбранный объект | Один выбранный объект; неизменённый выбор сохраняется при редактировании; узкий вариант перестраивается вертикально |
| Tabbed Workspace | Несколько независимых логических наборов | Grid Auto/*/Auto; TabControl, общий footer | Переключение вкладок не теряет ввод; ошибки указывают проблемный раздел |
| Results & Preview | Настройки и проверяемый результат | Две зоны в Grid; параметры рядом с текстовым preview/таблицей | Preview не подменяет результат; действия применения рядом с результатом; без декоративных схем листа |
| DockablePane Layout | Узкая долговременная панель Revit | DockPanel: footer Bottom, ScrollViewer с вертикальными секциями | Содержимое работает в узкой ширине; API вызывается через существующий ExternalEvent |

Не задавать глобальную одинаковую минимальную ширину всем окнам. Старые980×680 относятся к истории0.1, не к текущему эталону. Компактный диалог и DockablePane требуют своих обоснованных размеров; применимые проверки049/050 остаются обязательными при появлении таких поверхностей. Форма wireframe и требований: [LayoutSpecification](LayoutSpecification.md).
