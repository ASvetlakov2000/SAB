## Задача и границы

Источники: запрос текущего чата; `Docs/NotificationsAudit/{Audit,Approval}.md`; действующий `SAB/Notifications/NotificationController.cs` (Options, Settings, Failures, Dialog). Старое окно содержит только два широких уровня. Макет заменяет их конкретными правилами, но не вызывает старые handlers, не читает/не сохраняет `%LOCALAPPDATA%/RevitQuiet/settings.json` и не подписывается на Revit events.

Пользовательская последовательность: выбрать сообщение → прочитать исходный текст и последствия → выбрать действие → при зависимом удалении отдельно разрешить его → сохранить. Общий переключатель приостанавливает автоматический OK без потери подготовленных правил. Все исходные значения: показывать в Revit, авто-OK выключен.

Три действия: «Показывать в Revit», «OK + уведомление SAB», «OK + журнал». Последние два всегда предполагают журнал; отличаются показом карточки SAB. Для сообщений без обязательного OK, неизвестных окон, контура/профиля, владения и прав доступно только первое. Разрешение зависимого удаления действительно только для соответствующего сообщения и очищается при возврате к ручному показу. Дополнительные исключения регулируются отдельно; ошибки владения защищены даже при отключении исключения всей совместной модели.

Каталог использует реальные тексты из аудита и явно демонстрационные сведения о наличии OK. В живом Revit наличие кнопки и эффект OK у C01/C08 не проверены. В выбранной строке показывается статус «Демонстрационный диалог»; эта демонстрация не является разрешением или технической гарантией автоматизации.

## Две структуры

1. Таблица со всеми настройками в каждой строке: быстрое массовое редактирование, но длинные тексты, пояснения последствий и условное разрешение удаления перегружают строки.
2. **Master–Detail + Tabbed Workspace:** список сообщений и текущего действия слева, полный текст/последствия/редактор выбранного правила справа. Выбрана эта структура: список остаётся обозримым, опасное действие имеет явный контекст, длинный русский текст не расширяет таблицу.

Wireframe:

```text
Уведомления                         [Автоподтверждение OK] [switch]
Правила | Исключения | Журнал
Поиск сообщений [поле][Найти]    Показать [Все сообщения v]
┌ Сообщение / Действие ─────────┐  ┌ Выбранное уведомление ───────┐
│ строка44                     │  │ полный текст, тип и эффект  │
│ native bounded DataGrid      │  │ Действие [список]           │
│                              │  │ [разрешить удаление]       │
└──────────────────────────────┘  └─────────────────────────────┘
Показано N · Авто-OK N · Остальные показываются
Инструкция        Макет · тестовые данные        Отмена  Сохранить
```

Окно1160×820 DIP, minimum1040×700; поле деталей320DIP, gap20, внешние24. Таблица row44/header38 с собственным outline1/radius6; footer фиксирован. Справа bounded ScrollViewer; длинные сообщения доступны полностью. На minimum список уже, имена сокращаются с tooltip; выбранное полное имя остаётся в деталях. Без горизонтального scroll обычных колонок. Вкладки по текущему shared capsule40/14; три коротких заголовка не требуют нового wrapping-компонента.

Общие владельцы: существующий `SAB/UI/Styles/SABFluentLight.xaml` и прикреплённые свойства из существующего SAB.dll. Макет загружает scoped dictionary по исходному пути, не изменяет его и Application resources. Новых дублирующих шаблонов контролов нет. Изолированные DTO, INotifyPropertyChanged, ObservableCollection, ICommand и CollectionView принадлежат `Tools/UiShowcase/NotificationSettings`. API/Document/ExternalEvent в этом проекте отсутствуют.

Исключения: обязательные — контуры/профили, ошибки владения/прав, ошибки Revit, сохранение/синхронизация. Дополнительные — редактор семейств, изменение группы, совместные модели целиком. Сообщения без OK и неизвестные всегда показываются.

Журнал: макетные записи, поиск не добавляется без необходимости. Настраивается длительность карточки3–60с и папка макетного журнала; ввод проверяется до Save. Открытие журнала создаёт только demo HTML в `outputs/ui-production-preview/notification-settings`. Сохранение пишет только demo-settings.json туда же. Cancel/закрытие не пишут настройки. Инструкция открывает локальный Help.html этого макета.

## Проверка

До финала: целевая сборка standalone net48/x64; фактически показанное окно; снимки normal/configured/dropdown/delete-validation/delete-consent/protected/no-OK/unknown/empty/exceptions/journal/minimum/long-text. Routed events/selection/search/filter/dirty/save/cancel проверяются внутри WPF-хоста. Реальное нажатие мышью, полная accessibility/physical keyboard, OS DPI transitions и Revit операции отдельно NOT RUN. Изолированный макет не доказывает production UI или наличие OK в Revit.

Applicability каждого текущего registry ID и конкретные доказательства — `NotificationSettings-Report.json`; bounded независимый read-only review — `NotificationSettings-Review.md`. Существующий approval Fluent Light определяет оформление; approval этого макета ожидается отдельно.
