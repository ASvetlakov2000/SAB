# Исправление вёрстки трёх модулей SAB — 10.10.2026

Основание: новый запрос пользователя после отмены редизайна. Проверить и исправить
«Развёртки», «Создание видов и листов», «Параметризацию», сохраняя текущие дизайн
и функции. База: `5b616cbc` (откат к прежним окнам). Отклонённый редизайн не возвращён.

## Подтверждённые дефекты и изменения

| Дефект | Исправление |
| --- | --- |
| Прямоугольное содержимое закрашивало скругления основного окна развёрток и параметров | Внутреннее содержимое обрезается по существующему радиусу; контур и области изменения размера сохраняются |
| Последние столбцы списка помещений и видов/листов были недоступны при узком окне | Горизонтальная прокрутка таблиц включается при переполнении; остальная форма остаётся на месте |
| Расчёт свободного места таблицы учитывал системную ширину полосы вместо фактического viewport | Используется ширина ScrollContentPresenter с существующим оформлением полос |
| Левый захват заголовка определял соседний столбец неверно | Выбирается предыдущий видимый столбец по DisplayIndex; скрытые пропускаются |
| Группировка видов реализовывала все строки | Включена штатная виртуализация при группировке |
| Ширины столбцов параметризации принудительно переписывались на каждом SizeChanged | Сохранены пропорции и минимальные ширины; свободное место распределяет WPF, ручная ширина не сбрасывается |
| Колесо мыши останавливалось на границе вложенной таблицы | Внешняя форма получает колесо только после достижения границы внутренней прокрутки |
| Длинная подпись точки размещения измерялась без ограничения ширины | Заголовок использует ограниченный столбец и перенос; на узком окне элементы располагает прежний AdaptiveSettingsGrid |

Исправления `SabLayoutAssist` подключаются только к проверенным окнам. Общие цвета,
шрифты, рамки ввода, стили, анимации, вкладки, команды, привязки правил, выбор геометрии,
Revit API и транзакции не переработаны. Действующие WPF-UI и Nice3point зависимости
не обновлялись: задача не требует изменения совместимости .NET Framework 4.8.

Использованы UI UX Pro Max (рекомендации WPF по контейнерам и прокрутке), Impeccable
(две независимые оценки вёрстки и механики, локальные исправления и проверка),
frontend-design (сохранение действующего визуального языка), revit-external-events
(сохранение текущей границы UI/API; новая вёрстка не вызывает Revit API).

## Проверка

`Tests/UI.Layout` открывает реальные классы окон из собранного SAB.dll, а не
перерисованные макеты. Для развёрток коллекции представления заданы тестовыми данными:
конструктор, собирающий данные из документа Revit, здесь не выполняется.
Тест сохраняет и восстанавливает пользовательские настройки размеров окон.

- Исходный прогон воспроизвёл семь ошибок: углы двух окон, два последних столбца,
  отсутствие виртуализации групп, сброс ширины, захват колеса вложенной таблицей.
- Итоговый UI.Layout: 28 проверок, включая четыре угла, восемь native resize directions
  двух окон, 121 сгруппированную строку, 80 строк вложенной таблицы, достижимость последних
  ячеек, ручное изменение ширины, обе стороны захвата заголовка при скрытом столбце,
  внутреннюю прокрутку и передачу колеса в обе стороны и над пустой таблицей,
  границы полей отдельного окна настроек видов/листов при обычном и минимальном размере.
- InteriorElevations.WindowLayout: все вкладки при 699×1242, 559×994, 420×747,
  420×540, 980×720; границы полей и восемь направлений изменения размера.
- UI.Theme: 24 XAML-окна, фокус/валидация, редактирование, выпадающие списки,
  2000 строк, отступы полос, обычная и сокращённая анимация.
- ParameterTools.Preview: четыре вкладки, поиск параметров с сохранением GUID,
  настройка источника, таблицы значений, категории, сериализация и проверка запуска.
  Ожидание WPF Dispatcher добавлено перед проверкой отложенного расчёта ширин.
- ParameterTools: 91; ParameterTools.Write: 11; RoomResolution: 29 проверок с API doubles;
  InteriorElevations.SheetLayout: 31 336 assertions.
- Release-сборки и MSI для Revit 2022, 2023, 2024.

Снимки `outputs/layout-before` и `outputs/layout-after` получены из реальных классов WPF
вне Revit. Снимок 144 dpi проверяет рендер содержимого; это не тест изменения DPI монитора.
Операции создания видов/листов и записи в реальную модель внутри Revit в этом проходе
не выполнялись. Их подтверждение требует документа Revit и отдельного запуска команд.
