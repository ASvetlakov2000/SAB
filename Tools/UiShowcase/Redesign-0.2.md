# Исторический контракт SAB Fluent Light 0.2

Исторические уточнения0.3: [Refinement-0.3.md](Refinement-0.3.md). Высокие строки86 и sidebar300 ниже относятся к предыдущей версии; версия0.3 использовала общие строки44 и отдельные карточки sidebar380.

Пользователь отверг качество таблиц/списков 0.1, предпочёл Fluent Light, приложил изображение и потребовал новый дизайн. Последнее уточнение: из картинки брать оформление, кнопки, иконки, таблицы и композиционные приёмы; наполнение и логика строго из кода плагина. Два обязательных примера: «Параметризация» и «Создание видов и листов». Итог ещё не утверждён.

## Direction contract

THESIS: Новый визуальный слой для настоящих функций SAB. Таблица выглядит как данные, а не множество рамок. Никакой подмены действующей логики демонстрационным алгоритмом.

OWN-WORLD: Светлый фон #F6F7FA, белые поверхности, рамка #D6DEED, разделители #E4E9F0; синий #0F6CBD для основного действия/выбора. Segoe UI 24/16/13/12 DIP и исходные метаданные параметра 11. Контейнер 6, поле 4 DIP. Без теней и вертикальной сетки. Иконки действий — векторные линии. Новые templates не наследуют старый SABWindowStyles.

STORY: Параметризация — настроить реальные правила и их источники, проверить конфигурацию, сохранить профиль для отдельной команды записи. Виды/листы — выбрать структуру и образцы, заполнить таблицу, прочитать реальную валидацию и подтвердить создание. В preview подтверждение не вызывает сервис операции модели: Document не передан.

FIRST VIEWPORT: Оба диалога имеют служебную полосу SAB с видимой пометкой «Предпросмотр · тестовые данные · модель Revit не подключена», заголовок, белую рабочую поверхность и закреплённый footer. Параметры сохраняют четыре вкладки. Виды/листы имеют панель настроек слева 300 DIP, зазор 20, таблицу справа и исходный блок валидации под ней. Поле страницы 24 DIP. Главное действие справа внизу.

FORM: Пользователь закрепил референс, переопределив прежний seed c79b92d6 (7). Повторный случайный выбор не применяется. Референс — визуальная грамматика, не спецификация бизнес-функций. Сценарии и содержание взяты из реального SAB.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Layout Specification

Сравнение: единый макет Data Manager для обоих модулей против композиции по их реальной функции. Выбран второй: Tabbed Workspace для параметров, Data Manager для видов/листов. Первый скрывает источники, сопоставления и категории либо требует выдуманного UI. Не добавлять поиск таблицы, флажки выборки строк или preview вида только потому, что они есть в картинке.

```text
ПАРАМЕТРИЗАЦИЯ
SAB · модуль · пометка тестовых данных
Заголовок + исходное описание | экспорт / импорт конфигурации
Правила | Источники | Значения и сопоставления | Категории
[Все реальные поля активной вкладки]
[Пояснение правила + реальные действия с правилами]
Инструкция / статус                           Отмена / Сохранить

ВИДЫ И ЛИСТЫ
SAB · модуль · пометка тестовых данных
Заголовок + описание                                  Настройки
[Структура/образцы/   ]  [Импорт/экспорт, таблица, перенос имён]
[размещение/копирование] [10 исходных колонок + dynamic browser]
[прокрутка отдельно  ]  [Исходный блок валидации]
Исходный StatusText                              Отмена / Создать
```

Параметры: размер 1400×920, минимум 980×820 (поднят с 680 по визуальной проверке: при прежнем минимуме не помещалась целая строка с обязательными метаданными). Виды/листы: 1480×940, минимум 1100×760. Это размеры окна, клиентская область меньше на стандартный Windows chrome. Подвалы и действия остаются доступны, содержимое прокручивается отдельно.

Таблица видов/листов: шапка 38, строка 44, разделитель 1 DIP; без зебры, вертикальной сетки и постоянной рамки каждой ячейки. Параметры: автоматическая высота строки, минимум 86 для исходного ParameterPicker. Все его метаданные сохранены. Selection остаётся Extended из исходника; флажки Enabled и Required имеют исходный смысл. Состояние пустого поиска категорий объясняет отсутствие результатов и способ исправить запрос; выбор категорий не меняется.

## Источник функций и проверка

GenerateSourceViews.py создаёт только presentation overrides в ignored outputs. SourcePreview.targets собирает реальный SAB с ними в отдельный каталог. Исходные модели, VM, команды и сервисы компилируются без копии-имитации. XAML настройки/колонки/команды переносятся с проверкой полного инвентаря: 135 исходных binding-атрибутов, 10 колонок, 0 потерянных binding. Дополнительный StatusText — существующее свойство VM. 10 бизнес-методов SettingsWindow проверяются на идентичность тела. Из code-behind видов/листов в тестовой копии убраны только RestoreWindowLayout/SaveWindowLayout: пользовательская геометрия не читается/не пишется.

Хост передаёт синтетические Profile/RevitElementItem без Document. В capture проверены реальные Binding/Command, все четыре вкладки и три структуры, validation, редакторы, popup, пустой фильтр и исходный сброс до одной пустой строки. 19 снимков — native WPF RenderTargetBitmap. 144 dpi — рендер 150%, не системный DPI. Физическая мышь/drag/drop, полный keyboard traversal, accessibility automation, операции Revit и переход мониторов не заявлены.
