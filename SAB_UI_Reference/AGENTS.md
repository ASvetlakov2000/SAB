\## WPF UI rules for SAB



Все новые и изменяемые WPF-окна должны соответствовать общей стилистике решения SAB.



Обязательная спецификация:



`docs/ui/SAB\_UI\_STYLE.md`



Основной визуальный референс:



`docs/ui/references/CreateViewsAndSheets\_reference.png`



Перед изменением или созданием WPF-окна необходимо:



1\. Найти существующие ResourceDictionary, стили и окна SAB.

2\. Определить, какие существующие ресурсы можно переиспользовать.

3\. Прочитать `docs/ui/SAB\_UI\_STYLE.md`.

4\. Открыть визуальный референс.

5\. Составить краткий план изменения XAML.

6\. Только после этого изменять код.



Обязательные правила:



\* использовать существующие стили SAB;

\* общие стили выносить в ResourceDictionary;

\* не задавать цвета непосредственно в XAML окна, если существует общий ресурс;

\* не создавать отдельную визуальную систему для каждой команды;

\* не добавлять стороннюю UI-библиотеку без согласования;

\* не изменять ViewModel и бизнес-логику при задаче, относящейся только к дизайну;

\* сохранять существующие Binding, Command и ValidationRule;

\* code-behind использовать только для UI-действий, которые невозможно корректно реализовать через MVVM;

\* кнопка основного действия должна иметь сплошную синюю заливку;

\* вторичные кнопки должны быть контурными или нейтральными;

\* окна с таблицами должны использовать узкую левую панель настроек и широкую правую рабочую область;

\* действия строки располагать в порядке: вверх, вниз, добавить, удалить;

\* всегда проверять окно при минимальном размере;

\* после изменения запускать сборку решения;

\* перед завершением проверять XAML на отсутствующие StaticResource и DynamicResource.



Если визуальный референс и существующая реализация противоречат друг другу:



\* сохранить существующую функциональность;

\* использовать референс для визуального оформления;

\* сообщить о противоречии до изменения бизнес-логики.
